# 测试与验收范围

适用于 SteamGameBridge 0.2.0-preview.1。测试使用仓库目录内的模拟 Steam、账号 VDF、假游戏 EXE、假启动器及模拟 Starward 传输；不启动真实 Steam/游戏/Starward，不修改真实配置。测试结束只清理自己创建的夹具；不会结束正在运行的真实游戏。

## 自动化覆盖

Core 测试覆盖：

- 四个预设、自定义 AppID 与真实标题分离；多个 Windows 入口的明确选择，以及错误/缺失/过期元数据。
- 单项 VDF 修改、UTF-8 BOM/UTF-16 保留、重复键拒绝、未知字段和其他游戏参数保留。
- 多游戏共享账号并发接入、分别修复恢复；同一 Steam 安装/AppID 活动记录唯一。
- 三种旧启动项选择、确认后值变化、Windows 引号/中文/反斜杠/空参数、冲突参数顺序、完整命令检测与包装器占位符。
- 已有国际服清单、下载状态、未知内容、目录联接、路径重叠、部分操作中断后的恢复保护。
- 新配置列表独立保存、重复 AppID 拒绝；不访问旧版状态。

Launcher 测试覆盖：

- 从显式的 Steam 上下文启动；缺失/错误 AppID 拒绝，不设置或伪造生产 Steam 环境。
- 直接启动、官方启动器与包装器；假启动器先退出，工具仍等待真实假游戏进程。
- 完整路径、创建时间、当前会话、超时、重复会话保护与正常退出码。
- Unicode、引号、路径和 `--dx11` / `--dx12` 参数顺序保留；Steam 原始参数仅在显式占位符下传给包装器。
- ZZZ/HI3 URI、实际假游戏 PID、PID+创建时间去重、协议优先、手动 EXE 回退、缺失/失败后游戏正常退出。
- 对两种实际发布 EXE 各执行三种启动链。

本次基础检查为 Core 94 项、Launcher 61 项；加上每个发布 EXE 的 9 项检查后，Launcher 为每种版本 70 项。后续新增用例时，以该提交 CI 日志中的实际 RESULT 计数为准。

另包含 2026-10-23 从公开接口取得的四款游戏最小元数据快照；每个快照保留来源和采集日期。终末地当前确有两个 Windows 启动入口，需要明确选择。这些只是元数据验证，不代表真实启动通过。

## 构建与界面

```powershell
.\Build.ps1 -All -RunTests -Package
```

两种版本分别构建与运行。产物和日志在 artifacts 中，CI 同样保存测试证据。界面可使用 `SteamGameBridge.exe --demo` 进入只读演示：禁用保存、接入、修复、恢复和真实启动；不会自动读取真实 Steam 配置。演示中新列表和 Steam 路径为空是正常现象。

用户提供的 0.2.0-dev 演示截图已确认主界面、预设、AppID、三种启动方式和相关输入正常显示。下方设置在可滚动区域中。此截图不能证明真实配置操作或 Starward 实际统计已通过。按用户要求，后续没有使用 computer use 操作窗口。

## 窗口布局检查

`tests/SteamGameBridge.Ui.Tests` 在独立进程内创建隔离表单，不显示桌面窗口。检查最小、普通、宽屏尺寸的标签和按钮排版，渲染界面到测试目录；同时验证空闲维护检查保留控件状态、输入选区与滚动位置，以及界面的导航和窗口边界。使用说明保留操作步骤，省去重复的实现解释。

## 系统主题检查

用进程内的主题偏好替身检查浅色、深色及往返切换，覆盖输入、按钮、菜单、启动项弹窗和高对比度配色；检查文本对比度，以及切换后保留页面、选区和滚动位置。测试不修改 Windows 主题设置，也不打开桌面窗口。

## 真实会话验收（尚未完成）

以下必须逐项记录游戏名称、启动方式、日期、结果及证据，不能用自动化夹具替代：

| 项目 | 最小操作与证据 |
| --- | --- |
| Steam 正式条目 | 从所选 AppID 条目实际进入选定本地客户端，条目显示运行中 |
| Steam 原生游玩时长 | 对照启动前时长，运行后正常退出、同步，再检查增长 |
| 好友状态 | 好友端确认正式游戏名称、开始和结束状态 |
| Overlay / F12 | 实际游戏画面内分别测试 Shift+Tab 和 F12 |
| Starward 计时 | 游戏进程确认后发送请求，退出后在 Starward 对应国服记录中检查增长 |
| 无额外 Steam 下载 | 比较下载队列、下载日志与占位目录内容 |
| 更新后持久性 | Steam 和原游戏各自正常更新后，重复启动、维护与恢复验收 |
| 反作弊 / 权限 | 确认官方正常启动与权限；失败时记录，不修改反作弊或受保护文件 |

本次没有代替用户执行这些真实配置与账号操作。协议发送成功、PID 存在或 ACF 状态均不是这些项目的成功证据。
